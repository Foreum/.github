# Security Policy

Foreum takes security reports seriously. Please help protect users by reporting suspected vulnerabilities privately.

## Supported versions

Foreum is under active development. Until stable release support is formally defined, security fixes are handled on a best-effort basis for the current development version.

## Reporting a vulnerability

**Please do not disclose suspected vulnerabilities in a public issue, discussion, or pull request.**

If private vulnerability reporting is enabled for the repository, use GitHub's **Report a vulnerability** feature in the Security tab.

If that option is unavailable, contact the repository owner privately through GitHub and ask for a secure way to share the report. Do not include exploit details in a public message.

When reporting, include as much of the following as you can safely provide:

- A concise description of the vulnerability and its potential impact.
- Affected version, commit, or component.
- Steps to reproduce, proof of concept, or relevant logs.
- Any suggested mitigation.

Please avoid accessing, changing, or deleting other people's data while investigating a possible issue.

## What to expect

Foreum is maintained with limited resources. The maintainer will make a best effort to acknowledge and assess reports, communicate next steps, and coordinate disclosure after a fix or mitigation is available. A specific response time is not guaranteed.

Please give maintainers a reasonable opportunity to investigate and address the issue before public disclosure.
